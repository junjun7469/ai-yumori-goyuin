# onsen-sheet：温泉分析書 → 構造化 JSON ＋ 要確認フラグ

分析書の画像を、`docs/DATA_MODEL.md` の「2. 分析書 JSON」の形（見本：`data/maruso_analysis_2014.json`）にする。
**読み取りは Claude、原本との照合は人。** 読み取った数値は「原本未照合」のままで、断定しない。

## 守ること
- 数値は **画像に書いてあるものだけ**。読めない・不鮮明な値は推測せず `null` にして、`needs_verification` に「どの項目が読めなかったか」を書く
- 「効能」欄（適応症など）は構造化しない・要約もしない（医療表現を避ける。CLAUDE.md 絶対ルール3）
- 分析書の値は**源泉の値**。浴槽の値と同じとは書かない（`source_note` に原文の注意書きを残す）
- 施設の氏名・個人名・契約情報は JSON に入れない（施設名と所在地は既存のとおり）
- 読み取った日を `digitized_at` に、「読み取りは Claude、原本未照合」を `digitized_from` に必ず書く

## 手順
1. **画像を読む**（Read ツールで画像を開く）。次をこの順で拾う：交付番号・採取日・分析日・分析機関／泉源名・所在／泉質名（新旧）と分類（浸透圧・pH・温度）／現地試験（泉温・気温・湧出量・pH・電気伝導率・外観）／試験室（密度・pH・蒸発残留物）／陽イオン・陰イオンの `mg`・`mval`・`mval%`／非解離成分／溶存ガス／下段の「含有成分」の記載
2. **JSON を書く**。キー名と入れ子は `data/maruso_analysis_2014.json` に合わせる。mval% が表にあれば `cations_mval_pct` / `anions_mval_pct` として残す（検算に使う）。作業中のファイルは `data/` 以外に置く（確認後に移す）
3. **検査を走らせる**：
   ```
   node .claude/skills/onsen-sheet/check.mjs <JSONのパス>
   ```
   検査の中身（人の目でも同じ確認をする）：
   | 検査 | 内容 | 付ける要確認 |
   | --- | --- | --- |
   | mval% 合計 | 陽・陰イオンそれぞれの mval% の和が 100 か。合計欄と項目の和が合うか | 合計が 100 にならない群と、合わない欄 |
   | mg→mval の再計算 | 各イオンの mg ÷ 当量 ＝ mval か（±3%＋0.02） | 食い違うイオン名と計算値 |
   | 陽・陰の釣り合い | 陽イオンと陰イオンの mval 合計が近いか（差10%超で警告。酸性泉は水素イオンの未記載もありうるので原因は断定しない） | 両合計値 |
   | pH と泉質分類 | 酸性 pH<3／弱酸性 3〜6／中性 6〜7.5／弱アルカリ性 7.5〜8.5／アルカリ性 8.5〜 と、書かれた分類が一致するか | 現地・試験室それぞれの pH と分類 |
   | 浸透圧・温度の分類 | 蒸発残留物（8g/kg 未満＝低張性）、泉温（42℃以上＝高温泉）と分類が一致するか | 不一致の項目 |
   | **表内と下段の不一致** | 成分表の値と、下段の含有成分欄の値（Li・F・メタケイ酸・含有成分総量）が同じか | 項目名と両方の値 |
   | 分析から10年 | `analyzed_at` から10年以上経っていたら再分析の目安を確認 | 「施設に確認」（断定しない） |
4. **要確認を JSON に反映する**：検査が出した項目のうち、`needs_verification`（配列）にまだないものを手で追記する（check.mjs は「新規」を最後に表示する）。個別の値が怪しいときは、その値のオブジェクトにも `"needs_verification": true` と `note` を付ける（pH の例を参照）。**数値そのものは書き換えない**
5. **報告する**：「読めた項目／読めなかった項目」「検査で見つかった要確認の一覧」「原本で見てほしい箇所」を、専門用語を避けて短く伝える

## 出力の例（要確認の書き方）
- ○「pH（現地 2.01 ／ 試験室 1.87）が泉質分類『弱酸性』と整合しない。原本で桁・小数点を確認」
- ×「pH は 2.01 なので強酸性で危険」（断定・安全表現はしない）
