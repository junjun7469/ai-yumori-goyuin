# PRD — AI湯守ダッシュボード × 御湯印ガチャ

版：2026-11-03 初稿 / 期限：2026-11-08 20:00 JST

## 1. 誰の、どんな課題か

杖立温泉・丸正旅館の湯守（小野）は、91.5℃・185.7 L/min の源泉を毎日、温度・湯量・見た目・匂いで判断し、加水や設備を調整している。その判断は本人の頭の中にしかなく、本人がいなくなれば100年続いた湯の守り方は誰にも残らない。
一方、温泉に入る人は「どこで・いつ・どんな湯に入ったか」を残す手段がなく、温泉地ごとの湯の個性は伝わっていない。

**今回作るもの**：施設が湯の状態を記録し Claude が変化を検知する「AI湯守ダッシュボード」と、温泉地のキャラ入りデジタル御湯印を集める「御湯印ガチャ」。2つは1つのデータ基盤でつながり、丸正旅館の御湯印だけが「今日の湯」で動く。

**ハッカソン後**：小野が11/9から丸正旅館で毎日使う。杖立温泉の他施設に展開し、導入施設が増えるほど御湯印が生きる。

## 2. 成功条件（第1審査で上位6に入るために）

- 動画の冒頭15秒で「誰の・どんな課題」が伝わる
- 操作3つ（記録を入れる→Claudeが変化を指摘する→御湯印が今日の湯に更新される）が3分で見える
- Claude Code の Skill・サブエージェント・フックの使い分けが README とリポジトリで確認できる
- `docs/decisions.md` と `eval/` で試行錯誤の跡が見える
- 模擬データ・出典・医療表現の扱いが「安心して使える」水準

## 3. 画面と機能

### B2B：AI湯守ダッシュボード（施設向け、PC/タブレット）

| # | 画面 | 必須/任意 | 内容 |
| --- | --- | --- | --- |
| D1 | 基準値（分析書） | 必須 | 分析書の構造化表示。泉質、泉温、湧出量、pH、主要成分。要確認フラグと再分析時期の提示（断定しない） |
| D2 | 湯日誌の入力 | 必須 | スマホ幅で1分。チャンバー温度、浴槽温度、湯量（L/分・計測器の値）、見た目、匂い、作業内容、一言メモ。模擬データのプリセットも読める |
| D3 | 推移と変化検知 | 必須 | 直近60日の温度・湯量グラフ。Claudeが検知した変化を「要確認」として一覧。各項目に理由と「湯守なら次に見ること」 |
| D4 | 引き継ぎメモ | 小さく入れる | 蓄積した日誌と検知結果から、季節の癖・異常の前兆・対処の順序を1本のメモに生成 |

### B2C：御湯印ガチャ（一般向け、スマホ）

| # | 画面 | 必須/任意 | 内容 |
| --- | --- | --- | --- |
| G1 | ガチャ | 必須 | 1日1回無料で引く（課金なし）。演出は3秒以内。結果は温泉地キャラ＋代表泉質＋一言 |
| G2 | 図鑑 | 必須 | 47温泉地の一覧。持っている／いないの表示。地域で絞り込み |
| G3 | 御湯印の詳細 | 必須 | キャラ、温泉地、代表泉質、特徴、出典。丸正旅館だけ「今日の湯」（温度・湯量・一言、最終更新時刻、模擬データラベル）が表示される |
| G4 | 入浴記録 | 任意 | 「今日入った」ボタンで日付付きの御湯印を保存 |

## 4. Claude の役割（プロダクト内）

1. **変化検知**（Haiku）：日誌1件ごとに、分析書の基準値・直近14日・天候を照合し、`{ level: "normal"|"watch"|"check", reasons: [...], next_checks: [...] }` を構造化出力
2. **説明文**（Sonnet）：検知結果を湯守向け（専門用語あり）と宿泊者向け（やさしい言葉）の2通りに言い換え
3. **引き継ぎメモ**（Sonnet）：60日分の日誌と検知結果から1本のメモを生成。「要確認」の表現を守る
4. **分析書の構造化**（Skill、開発時）：画像→JSON、整合性チェック

ツール：`get_baseline(facility)`, `get_recent_logs(facility, days)`, `get_weather(date, place)`（実装はスタブでよい。模擬データ内に天候列を持たせる）。

## 5. 模擬データの仕様

- 基準：`data/maruso_analysis_2014.json`
- 期間：直近60日、1日1〜2件
- 変動：チャンバー温度は基準 91.5℃の ±10% 以内、浴槽温度は 41.5〜43℃（通常。41℃未満は要確認のため）、湯量は基準 185.7 L/分の ±10% 以内。冬季は泉温 -3〜-5%、降雨翌日は湯量 +5%・濁り「やや」、深夜は温度 -1〜-2%
- 異常シナリオ（`eval/scenarios.json` と対応）：湯量が3日連続で基準−8%以下になる／チャンバー温度が急に上がる（今回の模擬データには入れず eval のみ）／匂いの変化／濁りが続く。期間中に4件（湯量減少・匂い・濁り・浴槽41℃割れ）入れる
- 全データに `is_simulated: true`。画面は「模擬データ」バッジを必ず表示
