## 1. 技術
- **フレームワーク**：Next.js 15（App Router）、React 19、TypeScript 6、Tailwind 4。
- **DB**：SQLite（better-sqlite3）に Drizzle ORM。ファイルは `data/yumori.db` で、git には入れていません。
- **AI**：`@anthropic-ai/sdk`。変化検知は Haiku 5.5、引き継ぎメモは Sonnet 5.5。モデル名は `src/lib/models.ts` にまとめています。
- **テスト**：Vitest（92件）。評価は `npm run eval`。
- **起動**：`npm run dev` で http://localhost:3000 に立ち上がります。ポートは指定がなく、Next.js の既定値の3000です。
- **データ投入**：`npm run seed` で DB を初期化。`npm run sim` は模擬データの再生成、`npm run backfill` は検知結果の補完です。

## 3. 御湯印ガチャの仕様
- **キャラ画像**：`public/characters/` に6枚。01 登別、02 酸ヶ湯、03 花巻、04 鳴子、06 蔵王、43 杖立。残り41温泉地は `fallbackCharacter.ts` が泉質分類から SVG を作ります。
- **ガチャの決め方**：まだ持っていない温泉地から等確率で選ぶ（`gachaLogic.ts` の `pickArea`）。全部持っていれば全体から選びます。
- **1日1回**：匿名キー（`user_key`）ごとに、日本時間の暦日で判定。引いた日に再度押すと、その日の結果をそのまま返します。課金はありません。
- **匿名キー**：ブラウザの localStorage（`yumori_user_key`）に発行。ログインはありません。
- **取得記録の保存先**：サーバー側 SQLite の `goyuin` テーブル。`user_key`、温泉地、取得方法、取得日時、取得時点の「今日の湯」のスナップショットを保存します。端末側に持つのは匿名キーだけです。ブラウザのデータを消すと、その人の所持記録は引き継げません。

## 4. 「今日の湯」の受け渡し
あります。`getTodayYu`（`src/lib/goyuinData.ts`）が、AI湯守を導入した施設（今は丸正旅館＝杖立のみ）の最新の湯日誌を読んで返します。

- **返す内容**：チャンバー温度、浴槽温度、湯量、一言、最終更新、模擬データかどうかのフラグ。
- **一言の決め方**：日誌のメモがあればそれを使い、なければ検知結果の宿泊客向け説明を使います。
- **表示とスナップショット**：`/goyuin/43` の詳細と、ガチャの結果に出ます。ガチャで杖立を引いたときは、その時点の値をスナップショットとして `goyuin` テーブルに残します。
- **受け渡しの方法**：API ではなく、同じ DB を直接読む作りです。未来時刻の記録は出しません。
