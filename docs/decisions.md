何を決め、何を捨て、なぜかを日付付きで残す。審査の「試行錯誤の跡」にもなる。方針を変えるときは先にここへ追記する。

## 2026-11-02

- **テーマ1で出る**。例文「ベテランの仕事のやり方を、本人が現場にいるうちに次の人が受け継げる形にする」に、丸正旅館（100年・2026年承継）が直撃するため
- **AI湯守を軸にする**。5本柱のうち唯一「開発・実証準備」段階で、ハッカソン後も事業資産になる
- **「分析書の読み取りだけ」にしない**。禁止例「基本的なRAGアプリ」に見えるため。価値は日々の判断と引き継ぎに置く

## 2026-11-03

- **B2C「御湯印ガチャ」を追加し、2プロダクト構成にする**。ただしデータ基盤は1つ。丸正の御湯印だけ「今日の湯」が動く設計で、B2B と B2C を1本の線でつなぐ
- **代償として「湯守への問いかけ対話」を落とす**。引き継ぎメモ生成は1画面だけ残す
- **温泉地は 47（都道府県ごと代表1つ）から始め、151 へ拡張**。熊本は有名度なら黒川だが、実証現場の杖立を代表にする
- **キャラクターは小野が GPT / Gemini で生成**（共通指示文あり）。揃わない場合は泉質分類からの SVG フォールバック
- **47温泉地の泉質は「代表泉質（分類）」のみ**。数値は出典ありのみ。出典なしは「要確認」表示
- **模擬計測は分析書 ±10%**。全画面に模擬ラベル
- **ガチャは課金なし・1日1回**
- **ポケモンへの言及・類似は一切しない**。「151」は内部目標
- **モデル**：日次検知は Haiku、説明文と引き継ぎメモは Sonnet。理由：検知は毎回走るので安く速く、文章は質を優先
- **担当は固定しない**。補い合って進める
- **泉質の色分けキーは人が割り当てる（`src/db/springClass.ts`）**。CSV の代表泉質から機械的に判定すると「アルカリ性単純温泉（放射能泉を含む）」などで誤るため、47件を対応表で明示。複数泉質が並ぶ温泉地は mixed。色のためだけの分類で、画面の泉質表示は CSV の文言をそのまま使う
- **`source_url` は全件 null で投入**。CSV に出典URL列がなく、出典なしは画面で「要確認」表示にする方針のため。出典を確認できた温泉地から埋める
