# 御湯印図鑑・AI湯守の仕様メモ

README から移した、画面・機能の詳細。審査向けの概要は [README](../README.md)。

## 画面（開発サーバー起動後）

- AI湯守（施設向け）：`/dashboard/log` 湯日誌の入力と変化検知、`/dashboard/trend` 推移グラフ（直近60日・41℃/38℃の線・検知の印、クリックで理由）、`/dashboard/handover` 引き継ぎメモ（Sonnet が下書き、再生成可）
- 御湯印図鑑（一般向け・スマホ幅優先、下タブ4つ）：
  - `/goyuin` 図鑑（「取得した御湯印」を新しい順に、「御湯印を探す」は47都道府県のタイル地図と一覧）
  - `/goyuin/qr` QR（擬似スキャン）、`/goyuin/today` 今日の湯、`/goyuin/me` わたし（レベル・称号・地域の達成・実績）
  - `/visit/43` QR着地（例：杖立。ここで御湯印をもらう）、`/goyuin/43` 詳細（所持している温泉地だけ見られる）
  - `/goyuin/gacha` ランダムガチャ（構想として残している。下タブには出さない）

## 実装済み／擬似・サンプル／構想（未実装）

| 区分 | 内容 |
| --- | --- |
| 実装済み | 湯日誌の入力と変化検知（Haiku）、推移グラフ、引き継ぎメモ（Sonnet）。御湯印図鑑：湯の子の育成（下記）、地図、取得（QR着地）、図鑑、レベル・称号・実績、今日の湯、未所持の秘密化 |
| 擬似・サンプル | **QR読み取りは擬似**（/goyuin/qr はカメラを使わず、選んだ温泉地の着地ページへ移るだけ）。本番では、旅館に掲示したQRコード（/visit/[code] のURL）をスマホ標準カメラで読む想定。**丸正旅館の湯日誌データは模擬データ**（分析書を基準に生成。実測値ではない）。47温泉地のうち画像があるのは6か所で、残りは泉質の分類から作った仮の絵。称号と実績の名前は仮の言葉 |
| 構想（未実装） | 湯の子：泉質による姿の分岐の拡張、Claude が書く湯の子の日記、なりかわり達成でその土地の入浴剤が届く仕組み。記録の引き継ぎ（機種変更など。いまの匿名キーは端末のブラウザにだけ保存）、入浴記録（G4）、基準値（分析書）画面（D1）、実センサー連携、丸正旅館以外の施設の「今日の湯」 |

御湯印図鑑の仕様のうち、押さえておくこと：

- **未所持の温泉地は、名前・キャラ・泉質を伏せる**。画面で隠すだけでなく、サーバー（/api/areas など）が返さない。取得した瞬間に初めて見せる。ログインがないので、匿名キー（端末ごと）で所持を判定する
- 取得は、温泉地ごとに1日1回（日本時間）。温泉地は QR で決まり、柄（和紙・朝湯・夕湯・雪見）だけが等確率で決まる
- **御湯印の絵（カードの裏面）**：御湯印カード（図鑑・QR着地の結果・詳細）をタップすると、キャラ画像から「御湯印の絵」へ3D反転（0.6秒）でめくれる。QR着地の結果は、取得演出のあと自動で1回めくって絵を見せ、2秒後に戻す。絵の決め方は `src/lib/goyuinArt.ts`：`public/goyuin/<code>.jpg` があればそれ（杖立は 43.jpg）。なければ自動生成（和紙色の縦長の台紙に、温泉地名の縦書き・「奉湯」・取得日の漢数字・薄い朱印・四隅の湯けむり。CSS/SVG）。**絵の出典：`public/goyuin/` の絵は「TOJISM 制作」、自動生成の絵は「アプリ生成」**。ファイルの絵には日付を重ねず、取得日はカードの下に出す
- **模擬データの表示**：**丸正旅館の湯日誌は模擬データ**（分析書〔2014年〕を基準に ±10% で生成。実測値ではない）。画面の帯はやめ、模擬の数値（「今日の湯」の数値の横・一言の近く）に小さく「模擬」と出す。実測データ（`is_simulated` が false）のときは出さない
- **PC表示はスマホの枠に収める**：画面幅 768px 以上では、利用者側（/goyuin 配下と /visit）を 390×844px のスマホ枠の中に出す（汎用的な濃色の枠・カメラ穴・ホームバー。すべて CSS）。枠の中は独立してスクロールし、下タブ・起動演出もその内側。768px 未満の実機スマホでは枠なしの全画面。ダッシュボード（/dashboard）には付けない
- **見た目のテーマ**：既定は「レトロ携帯機風」（4階調の緑のドット画面。`html[data-theme="retro"]`）。従来の和の見た目は `washi`。「わたし」画面のボタンで切り替え、localStorage（`goyuin_theme`）に保存する。見た目だけの差し替えで、機能は同じ。ダッシュボードには影響しない。装飾・アイコン・柄はすべて自前の CSS / SVG
- **湯の子（ゆのこ）育成（実装済み・下タブ中央）**：最初は名前も姿も定まらない「たまご」を1体持ち、**入浴（/visit/[code] で御湯印を取ること）で育つ**。最初の入浴で通い始めた温泉地が決まり、**その温泉地に通った回数だけ**が増える（別の温泉地に入っても回数は増えない。同じ日の同じ温泉地は1回）。0回＝たまご／1回＝湯の子／2回＝湯の精（その温泉地の泉質の色をまとう：塩化物泉＝橙・硫黄泉＝黄・単純温泉＝水色・酸性泉＝薄紫・その他＝緑。分類は色分けのためで、泉質の断定ではない）／3回＝その温泉地のキャラクターに「なりかわり」。なりかわると図鑑のカードに「通い湯」の印が付き（取得とは別の印）、新しいたまごがすぐ生まれる。なりかわり1回＝300pt、実績「はじめてのなりかわり」。画面は `/goyuin/yunoko`、QR着地の御湯印のあとに「湯の子が育った」カード（3回目はCSSだけのなりかわり演出）。姿はすべて自前の SVG
- **思い出の写真**：御湯印の詳細（/goyuin/[code]）から、1御湯印につき2枚まで。サーバーで長辺1600pxに縮め、位置情報などの EXIF を取り除いて `data/photos/`（git 管理外）に保存する。端末の匿名キーに紐づくだけで、公開・共有はしない
- **デモ用の初期写真**：`public/memories/<code>/` に置いた JPEG（最大2枚）は、その温泉地の所持カードに「あらかじめ入っている思い出」として出る（例：`public/memories/43/tsuetate_01.jpg`）。**デモ用写真は代表者本人の写真**。アップロードと同じく縮小・EXIF除去して配信し、2枚の上限に数える
- **撮影用のデモ状態**（実データを消すので、撮影用の DB でだけ使う）：
  - `npm run demo-seed [-- <user_key>]` … 取得記録・湯の子・写真を消し、キャラ画像のある6温泉地（登別・酸ヶ湯・花巻・鳴子・蔵王・杖立）を所持にする。取得日は過去2か月に散らし、柄は4種が混ざる。**湯の子：杖立に2回通った湯の精（2/3）と、なりかわり済みの蔵王**を入れる（次に /visit/43 を取ると3回目でなりかわる。そのため杖立の最新の御湯印は今日ではなく3日前。雪見・今日の湯つき）。キーを省くと記録の最後の行のキー（ブラウザの localStorage `yumori_user_key` を渡してもよい）
  - `npm run demo-reset` … 取得記録（と写真）だけ全削除
